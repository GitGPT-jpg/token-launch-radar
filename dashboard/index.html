Token Launch Radar

Which protocol without a token would be worth the most?

A board of pre-token protocols, ranked by an implied value fitted from the snapshot itself — no names hardcoded, no price predicted. Every row carries its token odds, a note on what to trust, and a farm plan: what to do, what it costs, how long it takes.

How the value is worked out — the model, in full

Implied value = TVL × category multiple × size × growth × maturity. Every term is fitted on the snapshot's own token protocols, not picked by hand.

  1. Category multiple. For each category, the median market-cap/TVL of the protocols in that category that already have a token — shrunk toward the global median by a pseudo-count the fit chooses (k = ). A thin category (one token protocol) barely moves the global figure; a thick one owns its multiple. The multiple is clamped to 0.05 – 3.00. The table below shows the raw median beside the shrunk multiple, so the shrinkage can be checked.
  2. Size. (TVL / $100M) raised to a fitted exponent (). The snapshot's token protocols show the ratio falls as TVL grows — a log-log slope near −0.4 overall, −0.35 within a category — so giants are marked down and the board is not a TVL table.
  3. Growth. The protocol's 7-day TVL change, clamped to −50% – +100%, times a fitted weight (): growth = 1 + growth% / 100 × weight.
  4. Maturity. Age since the protocol was first listed, up to 730 days: maturity = floor + (1 − floor) × min(age, 730) / 730, with the floor fitted (). A protocol with no listing date counts as 365 days old.

How the four knobs were chosen. A grid search over all four, scored by held-out error — never by in-sample error. The 128 token protocols with a market cap above zero were split five ways by a hash of the slug (folds A to E, each protocol held out exactly once); each candidate was scored on a fold's validation protocols using only that fold's training protocols, and the score is the mean squared log error over every held-out protocol, each counted once. The candidate with the lowest score won, and the board uses those knobs with the multiples fitted on all 128. Three bounds on the grid are set by hand: the growth weight is at least 0.1, because the value model is defined to follow from TVL, seven-day growth and age, so a zero weight would leave one of its own inputs unused; the size exponent is at least −0.3, because the fit cannot tell −0.3 from its best of −0.4 on held-out error (within 1%) and the milder exponent keeps the size term an adjustment rather than the whole ranking; and the maturity floor is at most 0.9, because a floor of 1.0 would make the maturity term identically 1 and the model would ignore age. Token odds. How often protocols like this one have a token: the category's token rate and the age bucket's token rate, each shrunk toward the global rate of 19%, blended 70% category and 30% age. The odds never move the ranking; they tell the reader how likely the launch this board is priced for actually is.

Reading the top of the board. The top rows cluster in a few categories — risk curators and capital allocators — because those categories' token protocols carry the highest shrunk multiples and the largest TVLs, and the ranking is TVL-led: a board that ranked by anything else would not be a value board. The token odds up there look low, mostly under 15%, because most pre-token protocols never launch at all; the implied value is the value if one launches, and the odds say how often peers do. A reader may also recognise a name or two in the top ten as a token that trades; their records in this snapshot carry no token, so the rule ranks them, and the board reports the record — it does not claim the protocol has no token. The confidence strip on each row says when the evidence behind it is thin.

What to trust. Each row carries a confidence level. High means no flag: the category counted at least 4 token protocols, the growth and the listing date were reported, the multiple stayed inside its clamp, and the size adjustment is small. Every flag is listed on the row's detail view — thin category evidence, a clamped multiple, missing growth or listing date, or a large size adjustment. A large size adjustment flags the row because the value then leans on an extrapolation far from the $100M reference the fit anchors on, so the estimate is less certain the further the TVL sits from it. Three things the numbers cannot do: the snapshot carries market cap, not fully diluted value, so every multiple here is a market-cap multiple; 15 token protocols record a zero market cap and are left out of the fit, because a zero is a missing value, not a value; and within a category, token protocols' ratios spread by 10× or more, so any single multiple is an estimate.
